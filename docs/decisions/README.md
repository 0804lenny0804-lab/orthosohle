# Architekturentscheidungen (ADR)

Neue Dateien fortlaufend `NNNN-kurzer-titel.md` benennen. Zustände: vorgeschlagen, akzeptiert, ersetzt, verworfen. ADRs bei dauerhaft relevanten Entscheidungen verwenden: Modulgrenzen, BLE-Topologie/Protokoll, Board/Toolchain, Auth, Datenhaltung oder Hosting. Kleine lokale Refactorings brauchen keinen ADR.

Eine Routineentscheidung im beauftragten Umfang darf mit Begründung getroffen werden. Offene Team-/Hardwarefragen bleiben vorgeschlagen oder offen; irreversible externe Schritte brauchen den entsprechenden Auftrag. Bei Ablösung Nachfolger verlinken und alten ADR erhalten.
